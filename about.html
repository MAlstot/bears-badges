How BEARS badge verification works

A one-page overview for Baylor IT (proof of concept)

Proof of concept. Every record on this site belongs to a fake student.

The goal

Students who finish The BEARS AI Basics need a way to show it that a professor can check in seconds and that a student cannot fake with an image editor or an AI tool. The ATL also needs this to run without anyone issuing badges by hand.

The approach

The badge image is decoration. The proof is a small record file hosted on a site the ATL controls. A copy of a badge image cannot create a record on this site, so it fails the check.

The records follow the Open Badges 2.0 standard from 1EdTech, using its simplest method, called hosted verification. This is the same standard badge platforms such as Badgr (now Canvas Credentials) issue.

What is public and what is not

FileWhat it holds
issuer.jsonWho issues the badge: the Academy for Teaching and Learning.
badge.jsonWhat the badge is and what it takes to earn it.
assertions/<code>.jsonOne file per badge earned: the badge code, the date, and the student's email in scrambled (salted SHA-256 hash) form.
images/baked/<code>.svgThe student's copy of the badge image, with the link to their record built into the file.

Student names, Bear IDs, and grades never appear on the site.

How a check works

  1. The student shares their badge code and the email they used in the course.
  2. The checker page looks for a record file with that code. No file means no badge.
  3. The page scrambles the email the same way the record did and compares the two. A match means this badge was issued to this student.
  4. If the record is marked revoked, the page says so.

Anyone can also check a badge with a standard Open Badges verifier, using the record link or the student's badge image.

Known limits of this proof of concept

  • It is hosted on a personal GitHub Pages address. The trust a professor places in a badge depends on the address it lives on.
  • Badge records are created by running a script by hand, not yet pulled from Canvas.
  • Scrambling hides an email from casual viewing. Someone who already knows a student's email could still confirm whether that student earned the badge. Whether that is acceptable is a question for a privacy or FERPA review.
  • Badge codes can be seen in the site's file list. A code alone does not pass the check without the matching email.

What we would need from IT

  1. Hosting on a Baylor-controlled address, such as a Baylor GitHub organization with a baylor.edu subdomain.
  2. A read-only Canvas API token for the course, stored as a locked secret, so a scheduled job can issue badges each night when students finish.
  3. Guidance on a privacy and FERPA review of what gets published.
  4. A shared ATL email address to list on the issuer record.
